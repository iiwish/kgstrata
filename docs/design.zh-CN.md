# kgstrata 设计

[English](design.md)

这篇记录 kgstrata 背后的设计规则：要回答什么问题、层怎么对齐、数据契约的取舍、核心和插件的分工、构图、多层的比例、隐藏层和视觉规则。改样子之前先读它。

> 两张图加一个映射：本体层和物理层各是一张图，中间是本体落在哪些表上。两张图各占一个平面，映射走第三个方向。

## 要回答的三个问题

1. **对得上吗**：每个本体落在哪些表上，哪些本体没落地，哪些表没人认领。
2. **结构一致吗**：本体上的一条关系，在物理层能不能走通；物理层的一个外键，本体上有没有对应的关系。
3. **顺着怎么走**：本体上的一条路径对应物理层哪条 join 路径；改一张表会影响哪些本体。

现在的版本回答第 1 个，第 2 个只能靠「叠看」用眼睛对照，第 3 个只有简单的路径回放。

## 核心：上下对齐

两层不各自布局。先摆本体（主图层，按领域分扇区的力导），表落在它所映射的本体下方。映射是多对多的，所以对齐的单位是**对应块**：

- 每个本体挑分量最大的那条映射做主映射（一样大就挑对方连得少的，再按 id）；还没被挑中的表再各挑一条。
- 被主映射连在一起的是一个块。一对一的表正正落在本体下方；一对多的围着那个点散开；多对一的落在几个本体的重心下面。
- 没有映射的表排到外圈，朝着它外键邻居的方向。没有映射的本体留在原地——它在本体图里的位置本身是信息——下面没有线。
- 表之间的外键不参与定位：这样本体的一条关系和它对应的外键上下重合，叠看时能直接对照。

映射线分三种：主映射（近乎垂直）、块内的其余映射、跨块的次映射（细虚线）。

## 数据契约

对外的输入是四个扁平的列表：层、节点、关系、分组（`types.ts` 的 `StrataData`，第 2 版）。几条取舍：

- **关系只有一种**，层内还是跨层由两端在哪一层决定。每条关系有 id：能被选中、标注、对比，缺口状态也有地方挂。
- **`parent` 表示包含。** 子节点平时收进父节点，连到子节点上的关系上卷到最近的画出来的祖先，同类型的合成一条、分量相加。所以“映射的分量 = 对上了几个字段”不用手填，把字段级的映射写出来就有了。
- **整理和上卷是两步**（`resolve.ts`）。`normalize` 只查、只补缺省，什么都不丢：字段、字段级的关系都在。`project(数据, 展开了哪些节点)` 才生成要画的那张图。展开、收起只是换一个参数重新 `project`；布局用“全部收起”时的结果，展开出来的子节点围着父节点添上去（`placeChildren`），所以展开不会让图重新洗牌。
- **语义和呈现分开。** 节点只写 `type`，形状、等宽字由 `nodeStyles` 按类型配；组的颜色是可选的覆盖，缺省从主题色板取；对比专用的“谁吸收了谁”不放在节点上，交给看变化插件 `diff.show` 的参数。
- **分组分维度**，每层用自己的。扇区只分给基准层那个维度里的组。
- **每一层都是一张图。** 早先有过树、落点、外圈三种摆法，核心问题用不上，已经删掉；包含关系统一用 `parent`。
- **先查再用**（`resolve.ts`）。`validate` 列出问题，`normalize` 丢掉用不了的项。布局、样式、对比只吃 `project` 出来的结构（`Resolved`）：到了那里引用都有效，关系的 id 是必填的。
- **对外只认 id，不认下标，没有例外**：镜头、悬停和选中的事件（层、组给 id，名字另给）、变化的每一处都是。下标只留在给插件作者的 `StrataContext` 和 `kgstrata/internals` 里。程序选中和鼠标选中走同一条路（`select` 事件带 `source`）。视图状态（主次、隐藏、展开、选中、强调的组、聚焦的层、层距、镜头，以及插件登记的那几段，比如路径）可以用 `view` / `setView` 整个存取。
- **每帧的 `Looks` 里，额外的线各归各的。** `edges` 和底子一一对应；穿透线、路径、kgdiff 的标记分别在 `extra.bridges` / `extra.path` / `extra.marks` 里，不再靠数组里的位置约定。

### 交给 kgdiff 的是什么

`diff/adapter.ts` 把 `Resolved` 翻成 kgdiff 的图。原则是不丢信息、不借别的字段的名义：

- 节点的 `type` 是它自己的类型；在哪一层、哪个组是属性（`strata.layer` / `strata.group`）。
- 关系带着 id（按 id 认是不是同一条）和属性，分量放在 `strata.weight` 里：映射的分量变了、口径变了都算变化。
- 收在节点里的子节点记成属性 `strata.folds`：没展开时，加字段、删字段表现为“这张表的属性变了”和“上卷的映射分量变了”；展开以后看到字段本身的增删。
- 包含关系是一条 `strata:parent` 的层级边。kgstrata 自己加的东西都带 `strata` 前缀，不会和用户的关系类型、属性撞名。

要等 kgdiff 那边配合才能去掉的：布局结果是手拼的（`as unknown as LayoutResult`）；合并箭头、边的幽灵只有平面坐标，靠“找最近的节点”借层高，而上下对齐的节点平面坐标重合，可能借错层；颜色是 CSS 字符串，要自己解析。

## 核心和插件

核心 `Strata` 只管画一张多层的图：数据（normalize / project）、布局、模型、主次、隐藏层和穿透线、节点的展开、悬停和选中、强调的组、聚焦的层、镜头、每帧的循环、事件、视图状态。路径回放、看变化都是插件（`strata.use(plugin)`），核心不认识它们。这样只画 3D 图的人不用带上 kgdiff 和它的 WebAssembly。

**插件契约**（`plugin.ts`）：插件是 `{ name, install(ctx): Api }`，`use()` 把 `Api` 原样交回去。`ctx` 是核心给出去的能力，列得清清楚楚，私有状态不往外给：

- 读：全景的模型、现在画的模型、接管的是谁、渲染器、时间、减弱动效、隐藏的层、展开的节点、id → 下标。
- 用核心的规则：按选项整理数据（`normalize`）、按选项布局（`layoutOf`）。
- 改：接管（`takeOver`）和交还（`release`）、申请按现在的展开状态重建全景（`rebuild`）、跟随（`followTo(层的 id)`，可以带一个“换了主角就重新取景”的回调）、放开聚焦、选中、框住节点（`fit(节点的 id)`）或者盘面上的点（`fitPoints`）。
- 挂钩子：叠加层（`overlay`）、每帧（`onFrame`）、状态变了（`onChange`：换数据、全景重建、隐藏的层变了、有模式接管）、展开（`onExpand`：返回 true 表示这次由插件处理）、销毁、视图状态的登记（`registerView`）、核心的事件。

**叠加层和模式。** 叠加层叠在全景上：路径回放交给样式一串要强调的节点（`Spotlight`，样式据此压暗其余的——这一步要和聚焦、主次的压暗按顺序叠，所以放在样式里），再自己往 `Looks` 里写序号、`extra.path` 里的路径段和笔尖的涟漪。模式接管这一帧画什么：看变化换上两版合集的底子，`Looks` 由 kgdiff 出，“背景安静”的规则（没变的节点不出名字、没变的边压暗）也在它出 `Looks` 的那一步做完。同一时刻最多一个模式接管；接管时主角的分量按层的 id 对过去，隐藏的层照旧；看变化时展开、收起，插件接下这次展开、重新比一遍。

**每帧的 Looks 只有一条管线**（`pipeline.ts`）：① 基础样式（核心的 styler，或接管的模式）→ ② 叠加层（没有模式接管时）→ ③ 核心的统一后处理（隐藏层的淡出，全景和模式都走）。写入方各管各的：样式不知道路径，核心不知道 kgdiff 的“安静”。

**视图状态和镜头。** `view` / `setView` 只存取核心的那几项；插件用 `registerView` 登记自己的一段，存取时一并带上（路径插件登记 `path`，没装就没有这一项；类型用 `declare module` 补到 `StrataView` 上）。核心的镜头只有 `overview` / `top` / `layer`；框住路径、框住某一处变化归各自的插件，用 `ctx.fit`。核心里 `Strata` 只做编排，每一块事是 `src/engine/` 下的一个模块（见[模块](#模块)）；不需要 WebGL 的部分（主次的状态机、`setView` 的恢复顺序、每个镜头框哪些点、有隐藏层时的比例）是纯的，单独测。事件也一样：核心的事件不变，插件的事件走它自己的接口。

## 语言、主题和每个实例自己的状态

- **给人看的字都走消息表**（`locale.ts`）：校验的问题描述、报错、交给 kgdiff 的显示用标签（“关联”“包含于”）。机器读的不进表：问题和错误的 `code`、谓词（`strata:parent`）。缺省英文，`StrataOptions.locale` / `validate(data, { locale })` 换语言；看变化插件不写语言就跟核心。消息表是纯数据，不带 three，不带渲染的入口也用它。
- **主题按实例给**（`theme.ts`）：`DARK` 是冻住的缺省值，`createTheme(覆盖)` 每次出一份新的。主题从引擎一路传下去：模型（点阵色）、样式、渲染器的各部分（背景、盘面、标签的字体和描边）、路径、看变化（kgdiff 的底色方案）。纯计算的地方从选项拿：`normalize` 的色板缺省是 `DARK.palette`。每一项随时改都有效果：`fog.near` / `fog.far` 是镜头看着的那一点后面多远，每帧按它摆；只给 `background` 时背景渐变（`backdrop`）按它推出来，“换个背景色”一行就够。`<StrataCanvas>` 把面板要用的、和 `DARK` 不一样的颜色写成容器上的 `--kgs-*` 变量，面板跟着 `setTheme` 变。
- **没有模块级的可变状态**：雾的 uniform 一个渲染器一份，材质挂的是自己那份。剩下的模块级的东西只有纯缓存（十六进制色 → RGB、kgdiff 的颜色字符串解析）和常量表。
- **上下文丢失**：停掉循环、发 `contextlost`；还回来时 three.js 重建 GL 状态、资源按需重新上传，渲染器补上它不管的（清屏色、尺寸和后期的渲染目标、画布贴图），循环接上、发 `contextrestored`。

## 构图：一个主角，一个配角

两张图同等重要，但不同时当主角。同时摆两个一样大的盘，画面被平分，没有落点，信息量翻倍却没有主次——这是早先几版怎么调样式都不好看的根本原因。

- **主角那一层铺满画面**，原大、原亮，名字都出。默认是本体层。
- **其余的层是配角**：紧挨主角的缩到主角的 0.56，暗一档，只出最主要的几个名字；更远的更小更暗。本体当主角时，物理层在它下方露出来；物理层当主角时，本体层缩在它上方。
- **谁当主角是参数**：`new Strata(host, { hero: '层的 id' })`，不写就是第一张图；运行时用 `setHero(层的 id)` 换，`hero` 事件通知界面。位置和对应关系不变，只是换了谁大谁小。紧挨主角的那层缩到多大也是参数（`secondaryScale`，缺省 0.56），更远的层见下面“多层的比例”。
- **主次是连续的**：每张图有一个当主角的分量 0..1（`setHeroMix({ 层的 id: 分量 })`），1 原大原亮，0 是配角，大小、亮度、名字的多少都按分量走；`setHero` 只是把一层设成 1、其余设成 0。分量最大的那层算主角。两层都是 0.5 时一样大——这是过渡中的一个状态，可以停在这里，但不是推荐的常态：它就是早先那个没有落点的构图。界面上要不要给用户一根滑杆由接入方定，效果页里的「主次」滑杆只是演示。
- **主角可以跟着你在问的东西走**（`follow`，缺省关）：选中哪一层的节点、路径走到哪一层、看哪一处变化，主角就换到哪一层。只认“选中”，不认“悬停”——悬停就换会跳个不停。用户动过镜头以后，换主角只换大小，不抢镜头；路径回放时镜头本来就归它管，换主角时重新框住整条路径。
- 配角缩小之后，映射线不再垂直，而是收成一个锥面。对齐的性质还在：对得上的映射线互不交叉，交叉的就是对不上的。
- 「叠看」时两层一样大、压在一起，从正上方对照。

### 点一层

“我要看这一层”在每种情形下只有一个意思，事件和视图状态总是对得上：

- **几层并存：点一层就是让它当主角。** 主角本来就是“你在看的那一层”：它铺满画面，别的退后。再叠一个“聚焦的层”就是对同一个问题的第二个、互相打架的答案（0.1 里 `focusLayer` 换了主角，却发一个 `strata.focus` 里没有的 `focus`）。所以几层并存时 `focusLayer(id)` 就是 `setHero(id)`，`focusLayer(null)` 回到主角的“家”，不聚焦，`strata.focus` 一直是 `null`，只发 `hero`。
- **只有一层：没有主角**，`focusLayer` 保留它本来的意思：镜头框住这一层；`focus` 事件和 `strata.focus` 都是它的 id。

主次的几个设置方法返回实际生效的结果（`setHero`、`setHeroMix` 返回 `HeroInfo`，`setLayerVisible` 返回这一层的 `LayerInfo`）：引擎会调整请求——隐藏的层分量是 0，最后一张可见的图藏不了，全是 0 的分量当没给。把结果交回去比悄悄忽略清楚。

## 多层的比例

层数不限。不管几层，比例都由三条规则定（`stage.ts`，纯计算，有测试）：

**1. 离主角越远越小、越暗。** 主角原大。紧挨着的一层是主角的 0.56，再往外每层再乘 0.72（0.40、0.29……，不小于 0.24）。亮度同理：0.5，再往外每层乘 0.8。一摞层像透视一样往两头收，成一座塔，主次一眼看得出。

大小是**相对主角**说的，不是相对各层自己。各层本身有大有小——十个指标的盘比三十个本体的盘小——如果各缩各的 0.56，大层当配角时会和小层当主角时差不多大，主次就乱了。所以配角画多大 = 主角的半径 × 几成；本来就小的层不会因此被放大。

**2. 相邻两层在屏幕上搭一点边。** 层距不是固定值，按两层缩放后的半径之和来定：层大，隔得开；层小，靠得拢。配角之间不会互相压住，一摞小层也不会拖得很长。

**3. 整摞的宽高比有预算（不低于 1.45）。** 放得下时相邻两层搭边少一点，放不下时让配角往主角身后多收一点，但有下限。这样主角始终占住画面的大部分宽度，不会为了装下所有层把镜头拉得很远。

| 层数（主角位置） | 各层画出来的大小（主角 = 1） | 松紧 |
|---|---|---|
| 2（上） | 1 / 0.56 | 0.84，松 |
| 3（中） | 0.56 / 1 / 0.56 | 0.63 |
| 3（上） | 1 / 0.56 / 0.40 | 0.58 |
| 4（第三层） | 0.40 / 0.56 / 1 / 0.56 | 0.5，到下限 |

分量连续变化时（`setHeroMix`），每层的大小和亮度在“当配角的样子”和“原大原亮”之间按分量插值，层距跟着重算。

镜头按真实的透视投影贴着框（`CameraRig.frame`），不用包围球估——一头大一头小的一摞层，包围球会估得忽远忽近。

**布局的基准和主角是两回事。** 基准是别的图都向它对齐的那张图，缺省挑和别的图映射最多的那张（指标 / 本体 / 表里就是本体），也可以用 `anchor` 指定。主角不写时跟基准走。夹在中间的层的节点同时属于上、下两个对应块，指着它时两个块一起显出来。

## 隐藏层

层可以隐藏（`setLayerVisible`、`hidden` 选项）。只有显示和隐藏两种状态。

- **位置不动。** 不重新布局，剩下的层留在原位。
- **比例重算。** 隐藏的层不占位置，离主角几层远只数可见的层。层多了嫌挤，藏掉几层就松了。
- **关系穿透**（`bridge.ts`）。这一层自己的关系、它和相邻层之间的映射都不画了；被它隔开的两层之间，把两段映射接起来画成虚线。隐藏本体层，指标就直接连到它最终落的表上，分量是经过了几个本体。只接跨层的映射，不走层内的关系；一路往下走，不绕回同一层；连着隐藏几层也能接。落不到下面的节点没有穿透线——隐藏中间层等于做了一次端到端的缺口检查。
- **主角让位。** 主角被隐藏时让给最近的可见图。最后一张可见的图藏不掉。
- **路径跳步。** 路径经过隐藏的层，跳过那几步，前后两步之间画成虚线。
- **变化不能悄悄藏掉。** 看变化时隐藏一层，穿透线不画（那里的线由 kgdiff 管）；这一层有几处变化由界面标出来（效果页标在层列表里）。

## 视觉的规则

视觉以一张参考图为基准（原型的全景截图），每改一处都和它并排对比，不凭规则推。参考图的每一项都在中间：有光但很小很淡，有地面但只有一种颜色，有氛围但幅度很低。走过的弯路都是走极端——什么光都加，是光污染；全部删掉，成了线框图；颜色全部调饱和再全部压灰，也都不对。

| 东西 | 画法 |
|---|---|
| 地面 | 均匀的点阵铺满整个盘：同心圆上等距的小方点，一种蓝紫色，近大远小。没有边线，最外两圈略亮，轮廓是点出来的。下面一层极淡的领域底色 |
| 节点 | 一颗发柔光的珠子：饱和的领域色，芯略亮，外面一小圈很淡的晕。比想象的要小——画面要留白 |
| 层内的线 | 细的弧线，两端各取节点的颜色、中间渐变。越长拱得越高，有上限 |
| 映射线 | 发丝一样的直线，比层内的线再细一档、淡一档 |
| 名字 | 干净的白字，常规字重，近大远小。小层的名字全出；大层里长尾的名字悬停时才出。可以配（`labels`） |
| 背景 | 中间略亮的深蓝，四周暗下去 |

几条要守住的：

- **留白。** 节点小、名字少，线才舒展得开。节点画出来的半径只有布局半径的七成多。
- **颜色成片。** 每个领域在盘上占一片，颜色才是区域而不是碎点；点阵和底色只带一点点领域色去呼应。
- **点阵的轻重看屏幕上的密度。** 同样的点阵，盘铺满画面时是地面，盘缩小一半就成了一团。所以配角那层的点更小、更暗。
- **泛光只属于回答。** 静止时没有任何东西亮度超过 1（泛光阈值）。被指着的节点是一圈外环加稍亮的晕；它的邻居、同一个对应块里的节点一起显出来；别的连同点阵一起退后一步。
- **映射线不能粗。** 它们又长又多，粗一点就成了栅栏。
- **不给对应块另画形状。** 试过锥形的光柱，多余。基数从映射线的形状看。
- **核对效果要按真实像素看**，不能在缩小的截图上判断线宽和亮度。

## 其他

- 两层用同一种画法，只在形状上区分：本体是圆点，关系本体是菱形，表是暗底亮边的标牌。
- 看变化时颜色 = kgdiff 的五类变化，底子退成灰。空心只用于“这一版没有”。
- 平铺在盘面上的字只在从上往下看时显出来。
- 动效只用来解释，尊重 `prefers-reduced-motion`。

## React 封装

`kgstrata/react` 只是把引擎接到 React 上：`<StrataCanvas>` 在 effect 里创建、销毁（严格模式下各建各的），`data` 的引用变了才 `setData`；`useStrataState` 用 `useSyncExternalStore` 把 `layers`、`hero`、`expanded`、点中的层变成 React 状态，内容没变不换引用。面板只出带 `kgs-` 前缀的结构，样子在可选的 `styles.css` 里，位置交给用的人。边界照旧：`react/index`、`react/path`、`react/audit` 的引入闭包里没有 kgdiff；`react/diff` 经由 `kgstrata/diff` 带上它。

## 模块

| 模块 | 输入 → 输出 |
|---|---|
| `resolve.ts` | `StrataData` → `Normalized`（什么都不丢）→ `Resolved`（按展开状态收起、上卷） |
| `layout.ts` | `Resolved` → `StrataLayout`（位置、对应块、映射线分类；确定性，同输入同输出） |
| `styler.ts` | 数据 + 布局 + 交互状态 + 强调串 → `Looks`（平时、悬停、聚焦、强调） |
| `pipeline.ts` | 每帧的管线：① 基础样式 → ② 叠加层 → ③ 隐藏层的淡出 |
| `plugin.ts` | 插件契约（`StrataPlugin`、`StrataContext`、`StrataOverlay`、`StrataMode`）、事件、视图状态的登记 |
| `renderer/*` | `BaseNode[]` / `BaseEdge[]` + `Looks` → 画面（three.js，实例化） |
| `engine/index.ts` | 核心 `Strata`：只做编排，公开方法交给下面这些模块 |
| `engine/hero.ts` | 主次的状态机（纯的）：层的 id + 隐藏的层 + 动作 → 分量、主角、主角的“家” |
| `engine/hero-actions.ts` | 主次的动作：状态机接到排版、镜头和 `hero` 事件上 |
| `engine/layers.ts` | 隐藏层（按 id 记，淡出）、有隐藏层时的比例、什么时候算穿透线 |
| `engine/expansion.ts` | 数据到模型：整理过的数据、收起时的图和布局的缓存；展开的节点；重建模型 |
| `engine/shots.ts` | 镜头取景：每个机位框哪些点（纯的），再交给镜头 |
| `engine/pointer.ts` | 指针：悬停、点击、双击 → 节点下标；事件带的节点信息 |
| `engine/view.ts` | 视图状态：`view` 怎么拼，`setView` 按什么顺序恢复 |
| `engine/plugins.ts` | 插件宿主：`use`、`ctx`、模式的接管和交还、叠加层、每帧的管线 |
| `engine/loop.ts` | 每帧的循环、WebGL 上下文丢失 |
| `engine/core.ts`、`engine/types.ts` | 各模块共用的内部状态；公开的类型（`StrataOptions`、`StrataView`、事件带的东西） |
| `path/` | 路径回放插件：步骤 → 强调串；样式之后叠序号、路径段、涟漪 |
| `diff/` | 看变化插件：两版 `Resolved` + 布局 → kgdiff 场景；每帧 → `Looks`（唯一引入 `@kgdiff/*` 的地方） |
| `audit/` | 映射审计：`auditMappings`（纯计算，在 headless 里）和审计插件：收起来的模型，缺口用缺口色，选中的一项在上下两层里一起亮 |

入口：`index.ts`（核心，不带 kgdiff 和插件）、`path/index.ts`、`diff/index.ts`、`audit/index.ts`、`headless.ts`（不带 three、kgdiff），React 的 `react/index.ts`、`react/path.tsx`、`react/diff.tsx`、`react/audit.tsx`。契约在 `src/types.ts`。引擎不依赖 React；`demo/` 是效果页。
